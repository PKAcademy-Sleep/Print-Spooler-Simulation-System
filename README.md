# Spooler Lab

เว็บจำลองระบบจัดคิวงานพิมพ์จาก `print_spooler_v2.c` พร้อมคำอธิบายภาษาไทย สำหรับใช้ทดลองและนำเสนอในทีม พัฒนาด้วย HTML, CSS และ JavaScript โดยใช้ Node.js เปิดเว็บในเครื่อง

## เริ่มใช้งานแบบเร็ว

ถ้ามี Node.js และ npm อยู่แล้ว ให้เปิด Terminal ในโฟลเดอร์ที่มี `package.json` แล้วรัน:

```sh
npm start
```

เมื่อเห็น `Local: http://127.0.0.1:4173` ให้เปิด [เว็บจำลองในเครื่อง](http://127.0.0.1:4173) ด้วยเบราว์เซอร์ เก็บ Terminal นี้เปิดไว้ระหว่างใช้งาน และกด `Ctrl + C` เมื่อต้องการปิดเซิร์ฟเวอร์

**โปรเจกต์นี้ไม่ต้องรัน `npm install` และไม่ต้อง build ก่อนเปิดเว็บ** เพราะไม่มีแพ็กเกจ dependencies ที่ต้องติดตั้งเพิ่มเติม

## 1. เตรียมเครื่องสำหรับสมาชิกทีม

สิ่งที่ต้องมี:

- **Node.js พร้อม npm** สำหรับเปิดเซิร์ฟเวอร์และรันการทดสอบ เลือกรุ่น LTS ที่ยังได้รับการรองรับเมื่อติดตั้ง
- **เว็บเบราว์เซอร์** เช่น Chrome, Edge หรือ Firefox
- **VS Code** หากต้องการแก้โค้ด หรือใช้โปรแกรมแก้ไขข้อความอื่นได้
- **Git** เฉพาะกรณีรับและส่งงานผ่าน repository ของทีม

เปิด Terminal แล้วตรวจว่าเครื่องพร้อมด้วยคำสั่งต่อไปนี้:

```sh
node --version
npm --version
```

ทั้งสองคำสั่งควรแสดงหมายเลขเวอร์ชัน หากเพิ่งติดตั้ง Node.js ให้ปิดแล้วเปิด Terminal หรือ VS Code ใหม่ก่อนตรวจอีกครั้ง

> การเปิดเว็บจำลองไม่ต้องติดตั้ง GCC, Linux หรือ WSL เครื่องมือเหล่านี้ใช้เฉพาะเมื่อต้องการคอมไพล์โปรแกรม C ต้นฉบับแยกต่างหาก

## 2. รับไฟล์และเปิดโฟลเดอร์ให้ถูกต้อง

รับไฟล์โปรเจกต์จาก repository ที่ทีมใช้ หรือแตกไฟล์ ZIP ที่ได้รับให้เรียบร้อย หากใช้ Git ให้ clone ด้วย URL ของ repository ที่ทีมส่งให้

ใน VS Code เลือก **File → Open Folder…** แล้วเลือกโฟลเดอร์ที่มีไฟล์เหล่านี้อยู่ด้วยกัน:

```text
Print-Spooler-Simulation-System/
├── package.json
├── server.mjs
├── README.md
├── dist/
│   ├── index.html
│   ├── styles.css
│   ├── app.mjs
│   ├── engine.mjs
│   ├── guide.mjs
│   └── print_spooler_v2.c
└── tests/
    └── engine.test.mjs
```

จากนั้นเลือก **Terminal → New Terminal** โดย Terminal ต้องอยู่ในโฟลเดอร์เดียวกับ `package.json` ไม่ใช่ภายใน `dist`

สำหรับเครื่องเจ้าของโปรเจกต์ โฟลเดอร์ปัจจุบันคือ:

```powershell
cd "D:\Print-Spooler-Simulation-System\spooler-lab\PKAcademy-Sleep\Print-Spooler-Simulation-System"
```

**เพื่อนร่วมทีมให้ใช้ตำแหน่งที่เก็บโปรเจกต์บนเครื่องของตนเอง** ไม่จำเป็นต้องสร้างโฟลเดอร์ให้ตรงกับพาธตัวอย่างนี้

## 3. เปิดเว็บจำลอง

รันใน Terminal ของโฟลเดอร์โปรเจกต์:

```sh
npm start
```

คำสั่งนี้เรียก `node server.mjs` และควรแสดงข้อความ:

```text
Local: http://127.0.0.1:4173
```

เปิด [http://127.0.0.1:4173](http://127.0.0.1:4173) จะเห็นหน้า **Spooler Lab** พร้อมปุ่ม “เริ่มจำลอง”

- อย่าดับเบิลคลิก `dist/index.html` เพื่อเปิดแบบ `file://` เพราะเว็บต้องโหลด JavaScript modules และไฟล์ C ผ่าน HTTP
- ระหว่างใช้งานต้องเปิด Terminal ที่รันเซิร์ฟเวอร์ไว้ การรออยู่โดยไม่คืน prompt เป็นพฤติกรรมปกติ
- กด `Ctrl + C` ใน Terminal นั้นเพื่อปิด แล้วรัน `npm start` อีกครั้งเมื่อต้องการเปิดใหม่
- `127.0.0.1` หมายถึงเครื่องที่กำลังเปิดเบราว์เซอร์ เซิร์ฟเวอร์นี้รับการเชื่อมต่อเฉพาะในเครื่อง จึงส่งลิงก์นี้ให้เพื่อนเปิดจากเครื่องอื่นไม่ได้ เพื่อนแต่ละคนต้องรันโปรเจกต์บนเครื่องของตนเอง

## 4. วิธีทดลองสำหรับการสาธิตในทีม

1. ที่แท็บ **ห้องทดลอง** เลือกจำนวนเครื่องพิมพ์ 1–4 เครื่อง และเปิดหรือปิด **Aging** ก่อนเริ่ม
2. กด **เริ่มจำลอง** เพื่อให้ Producer 4 ตัวส่งงานตัวละ 5 ชิ้น รวม 20 งาน เข้าคิวร่วมที่มีความจุ 10 ช่อง
3. ดูงานในคิว งานที่เครื่องพิมพ์กำลังทำ และบันทึกเหตุการณ์ด้านล่าง
4. กด **หยุดชั่วคราว** แล้วกด **ทีละขั้น** เพื่อเดินไปยังเวลาที่มีเหตุการณ์ถัดไป เหตุการณ์ที่เกิดพร้อมกันจะอยู่ในขั้นเดียวกัน
5. เปลี่ยน **ความเร็ว** ได้ระหว่างทดลอง โดยไม่เปลี่ยนกติกาหรือผลของเวลาจำลอง
6. รอจนแสดง **จำลองเสร็จสิ้น** ตรวจว่างานพิมพ์เสร็จครบ 20 งาน แล้วดูเวลารอเฉลี่ย เวลารอสูงสุด และการแบ่งงานของแต่ละเครื่อง
7. กดปุ่ม **↺ เริ่มต้นใหม่** ก่อนเปลี่ยนจำนวนเครื่องพิมพ์หรือ Aging การเริ่มใหม่ล้างผลรอบก่อน จึงควรจดหรือถ่ายภาพผลที่ต้องการเปรียบเทียบไว้ก่อน

ตัวอย่างการเปรียบเทียบที่แนะนำ:

| รอบ | เครื่องพิมพ์ | Aging | สิ่งที่สังเกต |
| --- | --- | --- | --- |
| 1 | 1 เครื่อง | เปิด | งานที่รอนานได้รับระดับความสำคัญเพิ่มทุก 2 วินาที |
| 2 | 1 เครื่อง | ปิด | ลำดับงาน priority ต่ำและเวลารอเปลี่ยนไปอย่างไร |
| 3 | 4 เครื่อง | เปิด | การพิมพ์พร้อมกันช่วยระบายคิวและเปลี่ยนเวลารวมอย่างไร |

ทุกครั้งที่เริ่มใหม่ใช้ seed 42 จึงได้ข้อมูลชุดเดิมเพื่อเปรียบเทียบการตั้งค่า แต่ลำดับการรับงานอาจเปลี่ยนไปตามจำนวนเครื่องและ Aging อย่าสรุปล่วงหน้าว่าเปิด Aging แล้วเวลารอเฉลี่ยต้องลดลงทุกกรณี

อีกสองแท็บใช้สำหรับอธิบายประกอบการนำเสนอ:

- **ทำความเข้าใจโปรแกรม:** บทอธิบายภาษาไทย 9 ส่วน ครอบคลุมโครงสร้างข้อมูล Priority, Aging, Semaphore, Shared Memory, Process และสถิติ
- **สำรวจโค้ด:** อ่านไฟล์ C ต้นฉบับ เลือกข้ามไปยังฟังก์ชันที่สนใจ และดาวน์โหลดไฟล์ได้

## 5. แก้โค้ดและตรวจงานก่อนส่งให้ทีม

เปิด Terminal อีกหน้าหนึ่งในโฟลเดอร์โปรเจกต์ แล้วใช้คำสั่ง:

```sh
npm test
npm run check
node --check dist/guide.mjs
```

- `npm test` ตรวจตรรกะของแบบจำลอง เช่น ขอบเขต Aging, การเลือกงานเมื่อระดับเท่ากัน, คิวเต็ม, งานไม่หายหรือซ้ำ, สถิติ และการปิดเครื่องด้วย sentinel โดยชุดทดสอบปัจจุบันมี 13 กรณี
- `npm run check` ตรวจ syntax ของ `dist/app.mjs` และ `dist/engine.mjs`
- `node --check dist/guide.mjs` ตรวจ syntax ของไฟล์บทอธิบายเพิ่มเติม

หลังแก้ HTML, CSS หรือ JavaScript ให้บันทึกแล้วรีเฟรชเบราว์เซอร์ เว็บนี้ไม่มีระบบรีโหลดอัตโนมัติ การรีเฟรชจะเริ่มสถานะการจำลองใหม่ หากแก้ `server.mjs` ให้หยุดเซิร์ฟเวอร์ด้วย `Ctrl + C` แล้วเปิดใหม่

| ไฟล์ | หน้าที่ |
| --- | --- |
| `dist/index.html` | โครงสร้างหน้าเว็บและตัวควบคุม |
| `dist/styles.css` | สี ฟอนต์ และการจัดวางสำหรับหน้าจอขนาดต่าง ๆ |
| `dist/engine.mjs` | ตรรกะคิว Producer, Printer, Aging และเวลาแบบ discrete-event |
| `dist/app.mjs` | ปุ่มควบคุม การแสดงคิว เครื่องพิมพ์ สถิติ และบันทึกเหตุการณ์ |
| `dist/guide.mjs` | บทอธิบายภาษาไทยและหน้าอ่านโค้ด |
| `dist/print_spooler_v2.c` | สำเนาโปรแกรม C ต้นฉบับ |
| `server.mjs` | HTTP server สำหรับเปิดเว็บในเครื่อง |
| `tests/engine.test.mjs` | การทดสอบตรรกะของแบบจำลอง |

## 7. รันโปรแกรม C ต้นฉบับแยกต่างหาก (ไม่บังคับ)

ส่วนนี้ใช้เมื่อต้องการดูผลจาก POSIX จริง ต้องมี **Linux หรือ Linux ใน WSL พร้อม GCC** และรันคำสั่งใน Terminal ของ Linux ไม่ใช่ PowerShell โดยตรง

เข้าโฟลเดอร์โปรเจกต์จากฝั่ง Linux แล้วทำตามนี้:

```sh
cd dist
gcc -Wall -o spooler_v2 print_spooler_v2.c -lrt -lpthread

./spooler_v2       # 1 เครื่อง เปิด Aging
./spooler_v2 2 1   # 2 เครื่อง เปิด Aging
./spooler_v2 1 0   # 1 เครื่อง ปิด Aging
```

รันทีละคำสั่งและรอให้แต่ละรอบจบ โปรแกรมจะแสดงสถิติใน Terminal และสร้าง `spooler_log.txt` ในโฟลเดอร์ที่รัน โดยลบ log เก่าก่อนเริ่มรอบใหม่ หากต้องการเก็บผลเปรียบเทียบให้สำรอง log ก่อนรันครั้งถัดไป และไม่ควรเปิดโปรแกรม C หลายอินสแตนซ์พร้อมกันเพราะใช้ชื่อ shared memory กับชื่อ log เดียวกัน

## ขอบเขตของเว็บจำลอง

เว็บจำลองพฤติกรรมด้วย JavaScript ไม่ได้เรียก `fork()`, `mmap()` หรือ POSIX semaphore จริง และไม่ใช่ benchmark ของโปรแกรม C

เมื่อเหตุการณ์มีเวลาเท่ากัน เว็บประมวลผลการพิมพ์เสร็จ Producer ตามหมายเลข และ Printer ตามหมายเลข คิวใช้การสแกนเลือกงานและสลับงานท้ายตามต้นฉบับ ค่า semaphore บนเว็บเป็นสถานะหลังจบเหตุการณ์ จึงไม่แสดงช่วงล็อกระหว่างคำสั่ง

สถิติใน C ถูกบันทึกตอนเริ่มพิมพ์ แม้ชื่อตัวแปรจะเป็น `jobs_done` เว็บจึงแยกจำนวน “เริ่มพิมพ์” กับ “พิมพ์เสร็จ” ให้ชัดเจน เวลารอไม่นับช่วงที่ Producer รอช่องว่างก่อนเข้าคิวและไม่นับเวลาพิมพ์

การจำลองทำงานในเบราว์เซอร์โดยไม่มีการส่งข้อมูลการจำลองไปยังเซิร์ฟเวอร์ และมี WebMCP แบบ optional สำหรับอ่านสถานะและเดินเหตุการณ์ในเบราว์เซอร์ที่รองรับ
